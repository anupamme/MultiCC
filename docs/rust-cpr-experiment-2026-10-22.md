# Rust CPR 实验版与测试方法

日期：2026-10-22

## 当前状态

MultiCC 新增一份独立的 Rust CPR 代理内核，通过现有 napi-rs 原生模块嵌入。原来的 `cli-provider-router`（CPR）Node 实现保留，默认仍使用 Node。实验版只有显式打开隐藏环境变量后才参与代理请求。

本次成果尚在任务工作树，未提交、未合并、未部署；没有修改运行服务的配置，也没有重启 MultiCC。隔离测试已经完成，真实账号验收留给用户决定是否启用后进行。

## 隐藏开关与回退

在实际运行服务读取的环境配置中设置：

```dotenv
MULTICC_CPR_BACKEND=rust
```

回退时改成：

```dotenv
MULTICC_CPR_BACKEND=node
```

删除这一项也会恢复默认 Node。只接受 `node` 或 `rust`（忽略大小写及两侧空格），非法值会报错。开关在进程创建代理运行时时读取，更改后需要用户手动重启服务；不支持正在进行的请求中途切换实现。

配置位置依运行方式确定：源码服务通常读取服务目录的 `.env`；指定 `MULTICC_ENV_FILE` 时以实际配置文件为准；standalone 和桌面版使用其用户数据目录的 `multicc.env`。已有进程环境中的值优先于文件配置。不要把 `.env` 写进任务工作树，也不要依赖临时 shell 中的变量必然传到已注册的 launchd/systemd 服务。

该开关与现有 `MULTICC_PROVIDER_ROUTER_MODE=legacy|shadow|cpr` 分开：原有路由模式和管理功能保持原来的选择，只为 Claude/Codex 协议代理选择 Node 或 Rust 实现。没有新增公开设置项，也没有自动切换默认实现的逻辑。

显式选择 Rust 后，原生模块缺失、不可加载或 CPR 接口版本不匹配都会明确报错，不会在后台改用 Node。需要回退时显式改回 `node` 并由用户重启。此开关不改变 SQLite 等其他 Rust 功能的后端选择。

## 已实现的范围

这是一份针对 MultiCC 实际使用路径的 CPR 代理内核，并非把 CPR 的全部管理接口重写成了 Rust。

- Claude Messages：路由解析、子代理模型解码、供应商模型别名与上下文后缀改写、凭据请求规划、请求头整理、HTTP/TLS 转发。
- Codex 原生 Responses 和 Responses 兼容模式：供应商配置解析、命名子代理路由、请求整理、输出前的繁忙退避重试及兼容结束事件。
- 响应旁听：SSE 跨块 UTF-8、文本／推理／工具增量、缓存及普通 Token 用量、流内失败和限流头观测。正常代理路径按原始响应字节交付。
- 传输生命周期：连接与首包时限、客户端取消、输出背压、代理关闭、错误正文完整转发；超大错误不进入修复重试。
- 网络出口：复用宿主统一网络策略及官方账号专用出口插件的解析结果；Rust 自己建立连接，不创建 Node Agent。出口解析失败会终止请求，不会静默直连。

已退役的 Chat → Responses 桥不在 Rust 实验版支持范围，遇到该模式明确返回错误。需要该历史能力的配置应继续使用 Node。

CPR 的管理、接管、配置物化，以及 Codex 官方 OAuth 的宿主专属 relay 仍使用原有实现，不受此开关替换。不能把这些路径的成功归为 Rust 代理验证。

## Node 兼容层的保留原因

`src/providers/rust-cpr.js` 连接 Express 请求／响应、现有宿主授权、凭据读取与恢复回调、历史修复钩子、出口策略和用量事件。它调用已有宿主接口；新增路由规划、协议处理及网络传输核心位于 `native/cpr`。

保留这些 Node 接口是迁移桥接的需要：JavaScript 回调、Express 对象和当前 OAuth 管理器不能直接作为 Rust 业务对象传递。该层没有新建一套独立的账号或调度状态。Rust 通过异步 N-API 接口运行，网络 I/O 由 Tokio 执行，大请求的解析与序列化移至后台任务。

后续只有在宿主授权、账号凭据及事件总线提供明确的 Rust 接口，并完成同等契约验证后，才继续收缩这部分 Node 桥接；本次不改变它们的所有权和生产默认值。

## 构建与打包

源码版 `./multicc start` 沿用源码指纹缓存及自动构建流程，缓存位于主仓库 `data/rust-source/`。即使显式使用 Node SQLite，只要选择 Rust CPR，也必须提供或构建原生模块。源码构建需要 Rust/Cargo 和本平台链接工具。

standalone／桌面安装包必须携带包含 CPR 接口的目标平台原生模块，用户无需安装 Rust。打包校验已增加 CPR 接口检查；旧模块不能冒充新的实验版。当前仅构建和测试了 macOS ARM64 本机产物，尚未制作新的完整发布安装包。

本机测试产物：

```text
/Users/Zhuanz/Downloads/gapasea-all-in-one/code/claudecode/multicc/data/rust-cpr/2026-10-22/darwin-arm64/multicc_core.node
```

该文件放在主仓库的共享数据目录，不放进任务工作树，也不加入 Git。它仅适用于匹配架构的测试环境。其他机器和平台应重新构建匹配产物。

测试时 `MULTICC_RUST_ADDON` 指定运行时加载的单个模块，`MULTICC_RUST_PREBUILT_DIR` 指定打包复制模块的父目录；同时验证运行和打包时两者应指向同一份构建。只设置前者不能保证打包步骤复制新模块。

## 已完成的隔离验证

本机 macOS ARM64，Node 26.8.1：

| 验证 | 结果与边界 |
| --- | --- |
| Rust CPR 契约 | 12/12 通过，覆盖路径、模型、请求字节、凭据隔离、SSE、用量和限流头 |
| 新增代理集成 | 19/19 通过；含 Node/Rust 差分、宿主授权、OAuth 恢复、错误正文、取消、专用出口及统一网络策略 |
| Rust 与原有路由／账号组合回归 | 92/92 通过；此轮组合包含新增统一网络策略用例之前的 18 项代理测试，该用例另行通过 |
| 原有 OAuth／出口兼容套件 | 22/22 通过；预加载替换协议挂载入口，直接使用原有低层 Node handler 的测试仍验证保留实现 |
| 打包与安装相关测试 | 93 项，91 通过、2 跳过、0 失败；属于打包／安装夹具验证，未制作新完整安装包 |
| 静态和治理检查 | Rust fmt、workspace 全目标 Clippy（警告视为错误）、JS 语法、测试分层、源码行数、仓库产物和差异空白检查通过 |

差分测试比较了请求路径、凭据替换、模型改写、原始 SSE、增量事件和用量归因。错误场景覆盖认证重试只记一次账、超过 64 KiB 的错误正文、未结束认证错误的宿主超时取消，以及出口失效不直连。

复现新增集成测试：在项目目录执行，并把路径替换为自己机器的匹配产物。

```sh
MULTICC_RUST_ADDON=/absolute/path/darwin-arm64/multicc_core.node \
MULTICC_REQUIRE_RUST_TESTS=1 \
node --test tests/test-rust-cpr.js
```

## 用户启用后的验收重点

先合入并部署本次代码及匹配原生模块，再由用户选择测试实例，将隐藏开关改成 `rust` 并手动重启。建议覆盖 Claude 第三方与官方账号、Codex 原生 Responses、子代理、工具调用、长流式回复、中途取消、额度与用量，以及专用代理出口。可按同样步骤改回 `node` 比较。

真实供应商账号、实际长会话、Windows／Linux／Intel 平台和新完整安装包尚未验收。未做语言性能基准，不宣称性能提升。生产默认值继续保持 Node，后续是否改默认由用户测试结果决定。
