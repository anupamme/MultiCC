多电脑统一管理：三个版本

三套方案都建立在当前 Air 的骨架上（左栏 → 工作目录卡 → 控制台 / 定时任务 → 最近任务），差别在于「电脑」这个新维度放在哪一层。 每个原型都能点：顶部深色条里的「演示状态」按钮可以直接跳到关键画面。

从用户工作出发重新研究

下方三版保留为历史设计。最新独立重评重新核实了同类产品与当前代码，讨论统一待办、执行位置、离线恢复与连接方式，不沿用此前选型结论。

三套共用的底座（无论选哪套都要先做）

① 配对配对码 / 扫码 / 地址+令牌。配对码 5 分钟内有效且只能用一次；双方交换一枚只属于这对电脑、可单独吊销的令牌，存在服务端 0600 文件里（不进保险箱：保险箱会注入 CLI 环境变量）。
复用：ws-ticket、共享工作区的 SSRF 防护
② 电脑表每台电脑的名称、颜色、地址、令牌引用、上次在线时间。地址按每位用户自己的外网/内网入口填写，代码里不写死任何域名。
复用：外网穿透配置
③ 摘要接口每台电脑暴露一个只读的轻量摘要（在线、版本、负载、电源、进行中/等待/异常计数），供切换器、信号条、舰队卡片读取。
不复用 /api/air 全量快照
④ 远程屏幕跨机「🖥 屏幕」链接由目标电脑签发，前端只负责跳转。Windows/Linux 的 agent 未就绪时如实显示「不支持」。
复用：desktop-agent 协议

我的建议

三套不互斥，可以当成三个阶段：先上 A（底座 + 切换器，最快能用、风险最小），再在 A 的底座上叠 B 的聚合控制台（这才是「统一管理」的主体验），C 只挑「升级」和「配置同步」两块先做，迁移任务等真有需求再上。

如果只能选一套直接做到位，我推荐 B：入口不变（还是控制台），用户不用学新概念，手机端收益最大。

需要你拍板的问题

  1. 电脑之间是平等（任何一台都能当入口，A/B）还是固定一台主控（C）？
  2. 你的电脑之间能直接互通吗（同一局域网 / 各自都开了外网穿透），还是需要一个公网中继？
  3. 敏感信息（API key）要不要跨电脑同步？我的默认是不同步、逐条勾选。
  4. 任务跨电脑迁移是刚需吗？它是三套里最贵、最容易出问题的一块。
