0. 一句话结论

你打开的那台电脑当「中转站」：浏览器 / App 永远只连当前这台电脑；切到别的电脑时，所有 API 和 WebSocket 请求由当前电脑的服务端转发过去。 界面还是当前这台的 Air，数据换成那台的。这样无论手机在不在内网、那台电脑有没有外网地址，只要两台电脑之间能连通就能用。

2. 关键决策：浏览器怎么到另一台电脑

做法手机在外网 + B 只在内网https 页 → http 内网要不要登录 B版本不一致结论
① 直接跳转到 B 的地址✕ 连不上—每台都要登录一次无问题（用 B 自己的前端）只作为「在它自己的页面打开」的备选
② 浏览器跨域直连 B 的 API✕ 连不上✕ 被拦要把 B 的令牌交给浏览器有否决
③ 当前电脑服务端中转✓ A 走内网连 B✓ 浏览器只连 A不用，A 持有对 B 的凭证有，可检测提示采用

地址选择在服务端做：每台对端电脑可登记多个候选地址（内网 IP、外网穿透地址），中转站按「内网优先、外网兜底」探测并记住最近一次能通的那个。所以你说的「可以内网也可以外网」两种情况都覆盖，而且跟手机此刻在哪无关。

代价：多一跳延迟（局域网内 <5ms，可忽略；两边都走外网时会翻倍）；当前这台电脑关机，就切不到别的电脑（换一台电脑打开即可，平等的好处）。

3. 配对与凭证

3.1 流程（双向、平等）

B（要被加入的电脑）                         A（你正在用的电脑）
更多与系统 › 电脑管理 › 「允许被添加」
  → 生成配对码 K7Q-4M2（5 分钟、一次性）
                                           添加电脑：填 B 的地址（或从局域网发现里点选）+ 配对码
                                           A 服务端 → POST B /api/peers/pair
                                             { code, 自我介绍(名称/版本/机器指纹),
                                               给 B 用的凭证 credForB, A 的候选地址 }
  校验配对码 → 保存 A（credForB 只存哈希的对照）
  → 生成给 A 用的凭证 credForA，回传
  → 尝试按 A 的候选地址回连 A，成功=双向
                                           保存 B（credForA 存原文，用于发请求）
两边的电脑列表里都出现对方 ✓
  • B 回连不上 A（比如 A 是没开穿透的笔记本）也能配对成功，只是标成单向：在 A 上能切到 B，在 B 上看到 A 显示「对方可访问你，你访问不到对方」。
  • 配对码只在 B 上显示，必须本人在 B 前（或通过远程屏幕）才能拿到，防止陌生人用地址就把电脑加走。
  • 高级选项：直接填 B 的地址 + ACCESS_TOKEN，A 用它调 B 的配对接口完成同样的交换，之后不保存 ACCESS_TOKEN，只保存交换来的对端凭证。
  • 前提：B 必须监听在非 loopback 地址并配置了 ACCESS_TOKEN，也就是开了局域网模式或外网穿透（与 lan-discovery.js 的资格判断一致）。不满足时，「允许被添加」按钮直接说明缺什么。

3.2 凭证存哪

新文件 ~/.multicc/peers.json（0600，atomicWriteJson），和共享工作区的 external 状态同一种存法。 不放进敏感信息保险箱：保险箱条目会作为同名环境变量注入每个 CLI 子进程，等于让 AI 拿到另一台电脑的完全控制权。（上一版原型里写的「存进保险箱」是错的，已改正。）
  • 别人拿来访问我的凭证：只存 scrypt 哈希 + 盐（同 passwordHash），校验用定时安全比较。
  • 我拿去访问别人的凭证：存原文（必须能发出去），文件权限 0600；接口返回给前端时一律打码。
  • 每对电脑一枚凭证，任一侧「移除电脑」即吊销自己那一半，并尽力通知对方删除另一半。
  • 按规则要在运行时写入清单里登记这个新的 ~/.multicc 写入点（否则 CI deterministic 会红）。

3.3 对端凭证的权限

平等 + 同一个主人，所以对端凭证等同于已登录的远程管理员（和你在手机上登录一样），但永远不是「本机请求」：isLocalRequest 看的是 TCP 对端地址，中转来的请求天然是外部请求。 因此锁屏解锁密码、关盖运行这类「请在这台 Mac 上操作」的接口（host-power.js / host-write.js）会照常拒绝。这正是想要的效果，界面上提示「请在那台电脑上设置」即可。

4. 代理层（HTTP + WebSocket）

浏览器  ──/api/peers/mini/remote/api/sessions──▶  A 服务端
          (A 的 cookie 鉴权)                        │ 1. 校验浏览器是 A 的已登录用户
                                                    │ 2. 剥掉 Cookie / X-Access-Token / 转发头
                                                    │ 3. 加 X-Multicc-Peer: <credForA>
                                                    ▼
                                             B 服务端 /api/sessions
                                             auth.js 插槽认出对端凭证 → 放行（非本机）
  • 路径白名单：只转发 /api/*、/ws/*、/artifacts/*。B 上的 /api/peers/*（配对和对端管理）不转发，避免 A 借道去改 B 的电脑列表，也避免 A→B→C 链式跳转。
  • WebSocket：浏览器向 A 要一张绑定 /api/peers/mini/ws/chat 的 A 票据 → A 验票后用对端凭证向 B 的 /api/auth/ws-ticket 换一张 B 票据 → 连 B 的 /ws/chat?ticket=… → 双向 pipe。 B 侧 WS 鉴权（src/ws/connection-router.js）完全不用改。upgrade 转发复用 service-routes.js 的实现。
  • 大小与超时：沿用共享工作区的上限（请求体 10MB、普通请求 10s 超时）；上传/下载走流式 pipe，不进内存；WS 无总时长限制。
  • 可观测：每次转发带 x-correlation-id，响应头回带 X-Multicc-Upstream-Request-Id（同共享工作区），日志只记电脑 id、路径、状态码和耗时，不记 body。

5. 在线状态与摘要

不能让切换器去拉 /api/air：App 每 4 秒全量拉一次快照本来就是已知的流量热点，再乘以电脑数量会更糟。
  • 每台电脑新增 GET /api/peers/self/summary，返回几百字节：名称、系统、版本、协议号、在跑/等你/异常计数、电源、CLI 列表、是否支持远程屏幕。计数取自任务板 runState（唯一状态源）。
  • 中转站后台每 15 秒轮询各对端的摘要（失败后退避到 60 秒），缓存在内存里。浏览器只拉 GET /api/peers（本机缓存），切换器、「其它电脑」信号条、离线页都读它。
  • 状态机：online / offline（连不上，带上次在线时间）/ unauthorized（凭证被对方吊销，提示重新配对）/ incompatible（协议号不同）。
  • 对端从离线变在线、或有新的「等你回复」时，复用现有通知通道（Web Push / Bark）提醒一次，按电脑做冷却。

6. Web 前端改动

  • auth-client.js：加 ?machine=<id>，与 ?external= 同样改写 /api/*；multiccWsUrl 改成连中转站自己的 /api/peers/<id>/ws/*。两者互斥。
  • 切换 = 整页跳转到 /air?machine=mini（回本机就去掉参数）。Air 内存里各种缓存（任务板、目录、Provider）不需要逐个失效，最不容易出错；代价是切换时有一次刷新，约 1 秒。
  • 参数传递：Air 内部所有导航，以及对话 iframe（chat.html?air=1&task=…）都要带上 machine。在 auth-client 里统一兜底：同源导航与 iframe src 缺 machine 时自动补上，另外放一份到 sessionStorage 作为后备。
  • 链接改写：对方聊天里出现的 /artifacts/…、本地文件链接、#rs=control 远程屏幕链接，都指向那台电脑。点击拦截层（chat-local-links.js / chat-remote-links.js）在 machine 模式下把它们改到代理前缀。
  • 界面（按原型 A）：侧栏顶部切换器、页顶 4px 机器色条、面包屑首段、控制台「其它电脑」信号条、离线页、添加电脑三步对话框、「更多与系统 › 电脑管理」。新面板按 Air 面板登记的老规矩做（四件套 + air.html 顺序 + 断点），文案全部走 i18n。
  • 版本差异：前端是当前电脑的，API 是对方的。协议号相同但版本不同时，页头给一条可关闭的提示；协议号不同就不让切，引导「在它自己的页面打开」（直接跳 B 的外网地址，需要在那边登录）。

7. App 改动（第二步）

  • REST 请求是 buildHttpUrl 字符串拼接，把服务器地址设成 https://A/api/peers/mini/remote 就能直接复用。
  • 需要改三处：ws_ticket_service.dart 目前明确拒绝带路径的地址（第 83 行），票据接口也写死成 /api/auth/ws-ticket，要放开为「允许受信的前缀」并保持 issuedPath 校验；connection_probe_service.dart 两处 resolve('/…') 和 download_ticket_service.dart 一处 replace(path:) 会丢前缀，要改成拼接。
  • 侧栏顶部加同款切换器，数据读 /api/peers。它不是「换服务器」，而是在当前服务器内切换数据源，所以不碰已保存的服务器历史和推送注册。
  • 按记忆里的规矩：动 WsTicketClient 时测试桩必须回带 path，否则会静默无限重连。

9. 安全清单

  • 中转站必须剥掉客户端发来的 X-Multicc-Peer、Cookie、X-Access-Token、Authorization、Forwarded/X-Forwarded-*，防伪造、防把 A 的凭证泄给 B。
  • 对端地址只来自配对时登记的列表；每次请求都过 assertSafeRemoteTarget（防 DNS 重绑定），并禁止重定向跟随。
  • B 端校验对端凭证用定时安全比较；配对码限速（每 IP 每分钟 5 次），5 次错误作废当前码。
  • 对端凭证永不出现在前端响应、日志、聊天、托管上下文和环境变量里；/api/peers 只返回打码后的元数据。
  • B 的「电脑管理」里列出谁能访问自己、上次访问时间，可一键吊销。
