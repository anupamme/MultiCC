MultiCC 多电脑统一管理 · 方案 A · 第三轮调研

专门做多机互联的项目，都是怎么做的？

调研了 18 个项目，分三类：多机遥控 AI 编码代理（Happy、happier、Omnara、VS Code Remote Tunnels、Coder、Claude Code Remote Control 等），自托管多节点管理（Proxmox、Portainer、Cockpit、Netdata、Home Assistant、Plex、Unraid、Syncthing 等），以及组网层（Tailscale、Cloudflare Tunnel）。

0. 结论

① 没有一个项目让浏览器在同一个页面里直接调用另一台电脑的接口。Coder 的文档原话是「不支持浏览器直连」；Cockpit 做过类似的事，后来因为安全问题默认关掉了。
② 浏览器端只有两条成熟的路：一是由某台电脑在服务端转发，浏览器只连一个地址（Proxmox、Portainer、Coder、Happy）；二是每台电脑一个独立地址，切换就是整页跳过去（VS Code Tunnels、Cockpit 新版、Home Assistant 网页）。
③ 原生 App 一律直连：本地存一份服务器列表，滑一下或点一下就切换（Home Assistant、Plex、Jellyfin）。
④ 你要的「平等、没有主控」，Proxmox 有现成答案：每个节点都能当入口，登录任意一台就能管全部；入口挂了换一台登录即可。

对 MultiCC 的意思是：你倾向的「客户端来做」在 App 上完全成立，而且是业界标准做法；在浏览器上，「客户端来做」只能是整页跳转。要在浏览器里做到同页无感，只能由服务端转发，没有第三条路。

1. 五种做法

① 入口节点转发（同源代理）

Proxmox · Portainer · Coder 的网页端 · TrueCommand

浏览器只连一台，这台在服务端把请求转给目标节点。Proxmox 的每个节点都能转发，登录票据用集群共享的密钥签名，任何节点都能验票。

同页无感避开浏览器的所有限制多一跳

② 机器主动外连到中继

Happy / happier · Portainer Edge · Netdata · Home Assistant 云 · Claude Code Remote Control

每台机器只往外连，长连到一个中继或汇聚点，不需要开放任何入站端口，也不怕 NAT。Happy、happier 的中继可以自建，只转发加密数据。

外网手机也能看到只在内网的电脑需要一个常在线的中继

③ 原生 App 存服务器列表，直连

Home Assistant App · Plex · Jellyfin

App 存多台服务器，Home Assistant 三指一滑就切换，Plex 按「内网 → 外网 → 中继」依次探测。各台独立登录，彼此之间没有信任关系。

最简单切换快要求手机能直接连到那台

④ 每台一个地址，整页跳转

VS Code Tunnels（vscode.dev/tunnel/机器名）· 网页版 Home Assistant · 各种「切换服务器」

切换就是换一个地址打开，用一次性票据免去重新登录。整页跳转不受跨域、混合内容、Chrome 本地网络授权的限制。

实现最省事切换时刷新一次页面

⑤ 让 https 页面能直连局域网 IP（Plex 的绝招）

Plex（*.plex.direct）· Unraid（*.myunraid.net）

把 IP 编进域名：192-168-1-7.<机器哈希>.plex.direct 解析回 192.168.1.7，每台机器有一张通配证书。https 页面就能合法地直连局域网 IP。代价是要自己运营 DNS 和签证书服务，开了「DNS 重绑定防护」的路由器还会拦截。这是浏览器直连唯一成熟的解法，但对 MultiCC 来说太重。

2. 逐个项目

项目拓扑怎么加机器怎么切换对 MultiCC 的启示
Happy（Claude Code 手机遥控）手机和机器都外连到中继（可自建，MIT），端到端加密电脑显示二维码，手机扫码交换密钥同一 App，新建会话时用下拉框选机器选机器只是请求里的一个参数，不跳地址
happier同上，自建中继只要一条命令同一账号；可以 SSH 一键装好并注册远程机器同一 App，每个会话选「机器 + 目录」，可以把会话迁到另一台「SSH 一键添加」值得借鉴
Claude Code Remote Control（Anthropic 官方）本机外连 Anthropic，不能自建同一 claude.ai 账号统一会话列表，用主机名区分大厂也选择「外连 + 统一列表」
VS Code Remote Tunnels两端都外连微软中继code tunnel + GitHub 登录每台一个 vscode.dev/tunnel/<名> 地址，同一个域名同域名 + 路径区分机器，就没有跨域问题
Coder控制面 + 各节点外连；CLI 走 WireGuard 直连—同一个面板浏览器明确不直连，统一由控制面转发
Proxmox VE每个节点都能转发到其它节点复制加入信息（IP + 证书指纹）左侧资源树，同页切换「平等 + 同页无感」的范本
Portainer中心 Server；Edge Agent 主动外连并建立反向隧道一串加入密钥 + 一条安装命令环境卡片，同页切换反向隧道成熟，但是中心化
Cockpit入口机器 SSH 到别的机器并转发填 SSH地址变成 /@主机/反面教材：几台机器的网页脚本跑在同一个源里，一台被攻破就能控制其它所有台，已默认关闭。转发只转接口和数据，不转对方的前端
Netdata子节点外推到父节点；子节点可以列多个父节点，自动切换配置父节点地址和密钥父节点面板看所有子节点多个入口互为备份
Home Assistant各实例独立；云端只做 TLS 透传，看不到明文App 里添加服务器，局域网能自动发现App 三指滑动切换；网页版各开各的地址App 多服务器列表成本最低
Plexplex.tv 做目录 + 中继兜底账号登录App / 网页选服务器按「内网 → 外网 → 中继」顺序探测；plex.direct 证书
Syncthing每台各有自己的网页界面，没有跨设备管理设备 ID = 证书指纹，双方都添加才连通—双向确认的配对方式值得借鉴

另外看过：Omnara（中心化平台，偏重）、Claude Code UI（只支持单机，和 MultiCC 现状一样）、Remote Harness（一台当 Hub、其余外连，和 MultiCC 形态最像的小项目）、Unraid / TrueCommand（同 Plex / Portainer 的思路）、Jellyfin（客户端存列表）。

3. 浏览器的硬约束（已核实）

浏览器https 页面直连 http 内网 IP说明
Chrome普通请求要弹授权；ws:// 直接拦142 起普通请求需要授权，147（2026-04）起 WebSocket 也要。只有「公网页面访问内网」才会弹，内网之间、以及 Tailscale 的 *.ts.net 之间互访不弹。整页跳转不受影响。
Safari / iPhone一律当混合内容拦掉localhost 也不例外。唯一可靠的是「正规域名 + 正规证书」。
原生 App没有这些限制iOS 需要声明本地网络权限（App 已声明）；Tailscale 的 100.x 地址要走 https。
一个有用的发现：如果你的几台电脑都装了 Tailscale，并用 tailscale serve 拿到 机器名.xxx.ts.net 的 https 地址，那么从一台的页面去调另一台，不弹授权、证书合法，加上 CORS 就能在浏览器里同页直连。代价是手机也得装 Tailscale 并登录同一个账号。

4. 对 MultiCC 的建议（据此修正）

切换电脑      直连，本地存电脑列表（③）            整页跳到那台自己的 Air + 一次性票据（④）
              HA 式快速切换；内网 → 外网依次探测    不跨域、不碰混合内容、不弹授权；用的是那台自己的前端，没有版本差异
其它电脑状态  App 直接拉各台的摘要                  当前电脑的服务端去拉各台摘要（只读、只有计数）
                                                    浏览器只读本机接口，不撞任何墙
推送          每台电脑直接推给手机，点开自动切机    —
以后（可选）  —                                     Proxmox 式「每台都能转发」（①）：
                                                    同页无感 + 外网也能看只在内网的电脑；方案 B 也要用它
  • 第一步完全是「客户端来做」，符合你的倾向：App 直连；浏览器整页跳转也是浏览器自己完成的，服务端不转发任何对话或接口。
  • 唯一的服务端之间调用是拉其它电脑的摘要（几个数字），给浏览器里的切换器和「其它电脑」状态条用。这样浏览器端绕开了全部四道墙，也是 Netdata、Portainer 的做法。
  • Proxmox 式转发留作第二步：等你要做方案 B（统一控制台），或者确实需要「外网手机看只在内网的电脑」时再上。它和第一步不冲突，配对和凭证可以直接复用。
  • 借鉴：配对用 Syncthing / Happy 式的双向确认；加机器参考 happier 的「SSH 一键安装并注册」（远期）；转发时牢记 Cockpit 的教训，只转接口，不转前端。
  • 暂不做：Plex 式证书和 DNS（太重）、WebRTC 打洞（工程量最大）、自建公网中继（与「平等、自托管」不符，需要时再说）。
